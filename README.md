# Homecam — домашнее видеонаблюдение

Система видеонаблюдения, которая целиком работает в Docker: непрерывная запись с IP-камер,
живой просмотр с минимальной задержкой, архив с одновременным просмотром всех камер,
детекция движения, экспорт фрагментов, временные ссылки и оповещения в Telegram.

Стек: Ubuntu, Docker, Nginx, PHP 8.4, Laravel 13, SQLite, JavaScript (без сборки), FFmpeg,
go2rtc (ретранслятор живого видео в WebRTC/MSE).

## Возможности

### Запись
- Непрерывная запись с каждой включённой камеры (RTSP, а также HTTP-потоки, которые понимает FFmpeg).
- Видео **не перекодируется** (`-c copy`), поэтому нагрузка на процессор минимальная.
- Запись режется на ролики заданной длины (по умолчанию 60 с, настраивается у каждой камеры).
  Каждый ролик — самостоятельный файл MPEG-TS, который открывается в VLC, mpv, ffplay и других плеерах.
- Звук по желанию (перекодируется в AAC).
- Если камера пропала или перестала присылать данные, ffmpeg автоматически перезапускается
  с нарастающей паузой (2 → 60 с); ошибка видна в списке камер.

### Ротация
Раз в минуту суммарный размер роликов сравнивается с лимитом (`STORAGE_LIMIT_GB`, меняется в «Настройках»),
и самые старые ролики удаляются, пока размер не станет меньше лимита. Отдельно система следит,
чтобы на диске оставалось не меньше `MIN_FREE_GB` свободного места. Вместе с роликами удаляются
события движения за этот период и пустые каталоги.

### Онлайн-просмотр
- Сетка всех камер (1–4 колонки или автоматически), двойной клик или ⛶ — камера на весь экран.
- WebRTC с задержкой меньше секунды. Если WebRTC недоступен (закрыт порт 8555), плеер сам переключается
  на MSE через websocket (задержка 1–2 с), на старых iPhone — на HLS.

### Архив
- Интервал «с/по» и быстрые кнопки (1 ч, 6 ч, сегодня, вчера), выбор камер.
- Все выбранные камеры воспроизводятся **синхронно** по общей шкале времени; где у камеры нет записи,
  показывается «нет записи», остальные продолжают играть.
- Скорость 1×–16×, клик или перетаскивание по шкале — переход, пробел — пауза, стрелки ← → — ±10 с.
- Стрелки ◀ ▶ по краям шкалы сдвигают весь интервал на его длину назад или вперёд.
- На шкале синим отмечено, где есть запись, оранжевым — где было движение.
- Кнопки «◀ движение» / «движение ▶» переходят к предыдущему/следующему событию движения,
  галочка «только движение» при воспроизведении пропускает время без движения.
- Ссылку на открытый интервал можно скопировать из адресной строки.

### Экспорт
В архиве отметить «[ начало» и «конец ]» и нажать «Скачать фрагмент». Для каждой выбранной камеры
в фоне собирается один MP4 без перекодирования (до 24 часов за раз). Готовые файлы появляются на странице
«Экспорт» и хранятся `EXPORT_TTL_HOURS` часов (меняется в «Настройках»).

### Детекция движения
- Каждый записанный ролик анализируется в фоне (с низким приоритетом), задержка до ~1 минуты.
- Декодируются **только ключевые кадры** (у камер обычно раз в 1–5 с), уменьшенные до 128×96 в оттенках серого,
  и сравниваются с предыдущим ключевым кадром. На 6 камерах это около 7% CPU двухъядерного Core2 Duo.
- **Сила движения** — сколько процентов выбранной зоны изменилось между соседними ключевыми кадрами.
  Ориентиры: шум и снег до 0,5%, машина вдалеке 1–3%, человек рядом с камерой 3–30%.
- Резкая смена всей картинки (включение ИК-подсветки, фары, свет) движением не считается.
- Соседние срабатывания (с промежутком до 10 с) объединяются в одно событие с началом, концом и максимальной силой.
- Ограничение: движение короче интервала между ключевыми кадрами может быть пропущено.

Настройки каждой камеры («Камеры» → «Настроить»):
- включить/выключить детекцию и минимальную силу для события;
- **зона детекции** — прямоугольники, выделенные мышью на снимке с камеры (сетка 32×24);
  повторное выделение по закрашенному стирает; пустая зона = весь кадр;
- список самых сильных движений за сутки с их силой — помогает подобрать порог.

### Оповещения в Telegram
- **Камера недоступна / снова работает** — если от камеры нет видео дольше `CAMERA_OFFLINE_AFTER` секунд
  (меняется в «Настройках»).
- **Движение** — снимок с красной рамкой вокруг движения, время, сила и ссылка на этот момент в архиве.
  Настраивается у каждой камеры отдельно: включение, **своя зона оповещения** (например, только дверь),
  **минимальная сила** в этой зоне и «не чаще одного раза в N минут». По умолчанию выключено.
  О видео старше 10 минут (например, после перезапуска) оповещения не отправляются.

### Доступ
- Вход по логину и паролю (не больше 10 неудачных попыток за 5 минут с одного IP), несколько пользователей.
- **Временные ссылки** без пароля: только онлайн или онлайн + архив, все или выбранные камеры,
  ограничение интервала архива, срок действия; ссылку можно отозвать. По ссылке доступны онлайн, архив
  и экспорт в пределах разрешённого, но не настройки.
- Архив, экспорт и живое видео отдаются только после проверки доступа (nginx `auth_request` / `X-Accel-Redirect`).
- Пароли камер хранятся в базе в зашифрованном виде (ключ `APP_KEY`).

### Управление
- **Камеры** — добавление, настройка, удаление (с файлами записи или без), проверка подключения,
  статус (идёт запись / нет связи), объём архива и время последнего видео.
- **Настройки** — лимит хранилища, минимум свободного места, порог недоступности камеры,
  срок хранения экспорта, тест Telegram, пользователи, смена пароля.

## Как устроено

| Контейнер | Что делает |
|---|---|
| `app` | Nginx + PHP-FPM: веб-интерфейс, API, отдача файлов архива (через `X-Accel-Redirect`, после проверки доступа) |
| `worker` | `homecam:recorder`: по одному ffmpeg на камеру, индексация роликов, ротация, проверка камер, оповещения о недоступности; `homecam:motion`: детекция движения и оповещения о движении; `queue:work`: сборка экспортов |
| `go2rtc` | Живое видео: RTSP → WebRTC или MSE через websocket. Наружу доступен только через nginx с проверкой входа (порт 8555 нужен для медиатрафика WebRTC) |

База — SQLite в `state/homecam.sqlite` (камеры, пользователи, индекс роликов, события движения, ссылки, экспорт).

### Хранилище

```
<SERVER_CAM_DATA_DIR>/
  rec/<камера>/<ГГГГ-ММ-ДД>/<ЧЧ>/<камера>_<ГГГГММДД>_<ЧЧММСС>.ts   ← ролики
  exports/                                                         ← собранные MP4 для скачивания
```

Время начала записано в имени файла (часовой пояс `TZ`). Каталог `rec` можно скопировать куда угодно
и смотреть без этой системы. Если скопировать файлы обратно,
`docker compose exec worker php artisan homecam:reindex` заново построит индекс.

## Установка

1. Скопировать `.env.example` в `.env` и заполнить (сервер, `APP_KEY`, пароль администратора, лимит, Telegram).
2. С компьютера разработчика: `python tools/deploy.py` (нужен `pip install paramiko`).
   Скрипт загрузит проект в `/opt/homecam`, положит `.env` без SSH-учёток и выполнит `docker compose up -d --build`.
   **Внимание:** серверный `.env` при этом заменяется локальным.
   Вручную на сервере то же самое: `docker compose up -d --build` в каталоге проекта.
3. Открыть `http://<сервер>:8080` (порт `APP_PORT`) и войти под `ADMIN_LOGIN` / `ADMIN_PASSWORD`.
4. Для WebRTC открыть порт `WEBRTC_PORT` (8555, TCP и UDP).

Камеры добавляются в веб-интерфейсе («Камеры» → «Добавить»).
Из консоли: `docker compose exec app php artisan homecam:camera-add "Имя" rtsp://host:554/ --login=... --password=...`

### Доступ из интернета
- Сайт лучше отдавать через внешний nginx с HTTPS (Let's Encrypt), проксируя на `http://<сервер>:8080`.
  Для живого видео обязательно проксировать websocket:
  ```
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
  proxy_read_timeout 3600s;
  proxy_buffering off;
  ```
- Для WebRTC из интернета пробросить на роутере 8555 TCP+UDP и указать внешний адрес в `WEBRTC_PUBLIC`
  (домен или IP). Без этого живое видео пойдёт через MSE.
- Порт 8080 и RTSP-порты камер наружу не открывать.

## Настройки `.env`

| Параметр | Назначение |
|---|---|
| `SERVER_IP`, `SERVER_SSH_LOGIN`, `SERVER_SSH_PASSWORD` | сервер для `tools/deploy.py` (на сервер не копируются) |
| `SERVER_CAM_DATA_DIR` | каталог записей на сервере |
| `APP_PORT`, `APP_URL`, `APP_KEY`, `TZ` | порт и адрес сайта, ключ шифрования, часовой пояс |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | администратор, создаётся при первом запуске |
| `STORAGE_LIMIT_GB`, `MIN_FREE_GB` | лимит записей и минимум свободного места (можно переопределить в «Настройках») |
| `CAMERA_OFFLINE_AFTER` | через сколько секунд без видео камера считается недоступной |
| `WEBRTC_PORT`, `WEBRTC_PUBLIC` | порт WebRTC и внешний адрес для доступа из интернета |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_PROXY` | бот, группа и необязательный прокси |

## Telegram

1. Создать бота у @BotFather, получить токен.
2. Добавить бота в группу, узнать `chat_id` группы (например, через `https://api.telegram.org/bot<TOKEN>/getUpdates`
   после сообщения в группе; у групп он отрицательный).
3. Вписать `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`. Если api.telegram.org недоступен напрямую,
   добавить `TELEGRAM_PROXY=http://user:pass@host:3128` или `socks5h://user:pass@host:1080`.
4. Перезапустить: на сервере `docker compose up -d` в `/opt/homecam` (или `python tools/deploy.py --no-build` с компьютера).
5. «Настройки» → «Отправить тестовое сообщение».
6. Оповещения о движении включаются у каждой камеры отдельно.

## Полезные команды (на сервере, в `/opt/homecam`)

```
docker compose ps                          # состояние контейнеров
docker compose restart                     # перезапуск
docker compose up -d                       # перезапуск с новыми настройками .env
docker compose logs -f worker              # запись, ротация, детекция, ошибки камер
docker compose exec app php artisan homecam:reindex
```

## Если что-то не так
- **Зелёные кадры в браузере**, а экспорт нормальный — сбой аппаратного декодирования видео в браузере
  (чаще Firefox на Windows). Отключить аппаратное ускорение в браузере или обновить драйвер видеокарты.
- **Живое видео не открывается снаружи**, а сайт работает — внешний nginx не проксирует websocket (см. выше).
- **Шкала архива сплошь оранжевая** — в кадр попадает дорога или деревья: нарисовать зону детекции или поднять порог.
